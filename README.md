# PaySheet — бот расчётных листов

## Установка и запуск

Требуется Python 3.11+. Установите зависимости в отдельное окружение:

```bash
python3.11 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
nano .env
```

Заполните `BOT_TOKEN` токеном из `@BotFather` и `OWNER_IDS` числовыми Telegram ID главных администраторов через запятую. `ADMIN_IDS` — необязательный дополнительный список таких же ID. `.env` не публикуйте и ограничьте доступ: `chmod 600 .env`. Отправьте боту `/start` в личном чате.

Запуск для проверки: `python payroll_bot.py`. Команда `/cancel` отменяет текущий диалог и возвращает главное меню.

## Использование

### Сотрудник

После входа доступны три раздела: **📊 Расчётный лист**, **⚠️ Штрафы** и **📦 Пики**. В каждом разделе выбирается текущая или предыдущая календарная ISO-неделя. Для входа используйте логин из `Login` в Excel и пароль из CSV администратора; существующие аккаунты по ФИО также сохраняются. Telegram ID привязывается только к одной учётной записи, пароль хранится bcrypt-хешем. Пять неверных попыток блокируют следующий вход на 15 минут.

Расчётный лист показывает дневные количества, обработанные товары и сумму заработка, если для всех процессов найдены ставки. Пики считаются по строкам `Salary`, у которых `Process` содержит `Picking`. Штрафы берутся только из личных строк сотрудника в `Mistakes`. Если неделя/лист/тариф отсутствует, бот сообщает об этом, а не подставляет вымышленные значения.

### Администратор

Главное меню содержит **📤 Загрузить Excel**, **👥 Сотрудники**, **🔑 Пароли сотрудников**, **🔄 Сброс пароля**, **⚙️ Администрирование**. Функции доступны только пользователям из `OWNER_IDS`/`ADMIN_IDS` или администратору, добавленному через панель.

1. Нажмите **📤 Загрузить Excel** и отправьте XLSX. Для книги отчёта даты и ISO-недели определяются автоматически; один файл может содержать несколько недель. Старый формат единственной строки расчёта по ФИО можно загрузить через `/upload 2026-W47`.
2. Лист **Salary** должен содержать `Process`, `Login`, `Start Date` и колонки смен, названные датами/временем. Лист **NTT** — `Process`, `Login` и датированные колонки. Строки с одинаковыми логином/датой/процессом суммируются; значения остаются количествами, не денежными суммами.
3. В **Mistakes** импортируются `Login (нарушитель)`, `Дата совершения нарушения`, `Нарушение`, `Количество единиц/ нарушений` и доступные поля-пояснения. Для денежного расчёта добавьте **FineRates** с колонками `Нарушение | Сумма за единицу`. При отсутствии листа бот покажет нарушения без денежных сумм.
4. Для расчёта заработка добавьте **Rates** с колонками `Process | Ставка за единицу`. Сумма считается как количество × ставка для каждого процесса и дня. Если ставок нет для части процессов, общий итог не показывается как полный.
5. Логины из Salary/NTT/Mistakes создаются как отдельные аккаунты. Они не связываются автоматически с аккаунтами ФИО: в этой книге ФИО отсутствуют. Для первого доступа нажмите **🔑 Пароли сотрудников** и передайте каждому логин и случайный пароль из приватного CSV. Пароли ранее созданных аккаунтов не выдаются повторно.
6. Если импорт затрагивает уже загруженные недели, бот запросит подтверждение; все недели файла сохраняются транзакционно. Другие недели и пароли не теряются.
7. **👥 Сотрудники** присылает CSV со списком и статусом входа. **⚙️ Администрирование** позволяет управлять администраторами и просматривать статус; действия доступны только администраторам. `/status` показывает статус бота.

Файл `NK Report FC2.xlsx`, предоставленный для проверки, успешно читается: в нём есть Salary, NTT и Mistakes. Его данные заканчиваются 03.11.2026, а листы Rates и FineRates отсутствуют. Поэтому для календарных недель 09–15 и 16–22 ноября этот файл не содержит записей, а денежные суммы нельзя вычислить до добавления тарифов. Бот покажет это явно и не создаст примерные суммы.

Числа выводятся с точностью до двух знаков с округлением `Decimal`, разделителями тысяч и сохранением нулей. Пустая ячейка показывается как `—`; вычисления вместо значений Excel не выполняются.

## Данные и резервирование

`payroll.sqlite3` содержит персональные данные, расчёты, bcrypt-хеши, роли и активные состояния диалогов. Он создаётся автоматически, работает в WAL-режиме и доступен только владельцу процесса. Не удаляйте его при обновлении кода. Перед обновлением или периодически делайте резервную копию штатным способом SQLite (`sqlite3 payroll.sqlite3 ".backup 'payroll-backup.sqlite3'"`) и храните её в каталоге с ограниченными правами. Папка проекта должна быть доступна только пользователю бота.

Проверки: `.venv/bin/python -m unittest -v`. На рабочем сервере используйте Python 3.11+.

## VPS и автозапуск через systemd

1. Скопируйте проект в `/opt/payroll-bot`, создайте там окружение Python 3.11+, установите `requirements.txt`, заполните `.env` и выполните `chmod 600 .env`.
2. Скопируйте `payroll-bot.service.example` в `/etc/systemd/system/payroll-bot.service`, замените `CHANGE_ME` на системного пользователя с доступом к каталогу, затем:

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now payroll-bot
sudo systemctl status payroll-bot
sudo journalctl -u payroll-bot -f
```

systemd перезапускает процесс при сбое и корректно останавливает его при перезагрузке. Для деплоя используйте SSH/SCP или Git без `.env`, `.venv` и базы. Передавать доступ к серверу или токен бота посторонним нельзя. При смене токена обновите `BOT_TOKEN`, затем выполните `sudo systemctl restart payroll-bot`.

## Railway (бесплатный план)

В репозитории есть `Dockerfile` для Python 3.11. При подключении GitHub-репозитория Railway обнаружит его автоматически.

1. Создайте сервис из репозитория и установите переменные `BOT_TOKEN`, `OWNER_IDS` и при необходимости `ADMIN_IDS` в настройках Railway. Никогда не загружайте `.env` или токен в репозиторий.
2. Создайте и подключите к сервису постоянный Volume с точкой монтирования `/data`. Путь базы задан как `/data/payroll.sqlite3`; без Volume SQLite и сессии бота могут потеряться при новом деплое.
3. Используйте одну реплику: SQLite не предназначен для нескольких одновременно запущенных экземпляров бота.
4. Не включайте serverless auto-sleep. Long polling бота отправляет запросы Telegram, что обычно не даёт сервису уснуть, но платформа всё равно может остановить сервис при исчерпании доступных кредитов/лимитов.

Railway Free предоставляет $1 месячного кредита на использование и ограничивает бесплатный сервис ресурсами; расход зависит от фактического потребления. Поэтому постоянная работа без перерывов не гарантируется. Если бюджет строго $0, не подключайте платный план или способ оплаты; при исчерпании кредита бот может остановиться. Следите за Usage в Railway. Официальные сведения: [тарифы](https://railway.com/pricing), [постоянные тома](https://docs.railway.com/volumes).

В `.dockerignore` исключены `.env`, локальная SQLite-база с персональными данными, виртуальное окружение и логи. После первого запуска бот создаст пустую базу на Volume. Чтобы загрузить сотрудников в production, отправьте Excel владельцем через Telegram-бота. Не копируйте существующую `payroll.sqlite3` в сторонний сервис.
